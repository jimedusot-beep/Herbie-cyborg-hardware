# H.E.R.B.I.E. engineering integration audit — 2026-10-21

**Scope:** Repository tree inventory plus inspection of key README, CAD inventory, assembly manifest, software motion adapters, unit tests, PRs and available GitHub Actions results. This is a **targeted audit**, not a line-by-line certification of every source file or full electronics design review.

## Sources inspected

- [Herbie](https://github.com/jimedusot-beep/Herbie): roughly 222 main-branch Git tree entries at initial audit, with browser app, many simulation workbenches, `hardware/README.md`, test folders and GitHub Actions workflows.
- [3D-vision](https://github.com/jimedusot-beep/3D-vision): roughly 131 main-branch Git tree entries at initial audit; `HERBIE_V1/PARTS.csv` defines 18 provisional CAD part IDs, `HERBIE_V1/CAD/` has editable OpenSCAD, GLB/STL model exports, and `EXPERIMENTS/001_HERBIE_SKELETON/assembly_manifest.json` describes five skeleton transforms with `electronics_placeholders_not_measured: true`.
- [Herbie-cyborg-hardware](https://github.com/jimedusot-beep/Herbie-cyborg-hardware): newly initialized repository; initial electronics structure and automated checks proposed in [draft PR #1](https://github.com/jimedusot-beep/Herbie-cyborg-hardware/pull/1).

## Confirmed working *software* evidence

- Herbie has scripted face, camera and pan/tilt software prototypes. None demonstrates motorized physical motion or a physical emergency stop.
- 3D-vision has working CAD file viewing and tests; [the workshop testing job](https://github.com/jimedusot-beep/3D-vision/actions/runs/39646448492) succeeded while WebKit initially reported an animation save/reload assertion. A targeted rerun of that job subsequently passed. The initial failure should be investigated if repeated.
- Hardware PR #1 has Python inventory tests and GitHub Actions CI to check component records and provisional cross-repository mappings. Passing checks are *not* electrical safety tests.

## Confirmed design inconsistencies

1. **Hardware repository name:** older engineering docs referred to non-existent `Herbie-Hardware`; actual name is `Herbie-cyborg-hardware`. Corrections proposed in [Herbie PR #58](https://github.com/jimedusot-beep/Herbie/pull/58) and [3D-vision PR #3](https://github.com/jimedusot-beep/3D-vision/pull/3).
2. **Simulated protocols:** two independent version-1 virtual motion envelopes differ in command names and reset semantics. See [comparison](MOTION_PROTOCOL_COMPARISON.md) and [tracking issue](https://github.com/jimedusot-beep/Herbie/issues/60). Neither is an approved physical controller protocol.
3. **Physical CAD:** 18 part geometries and a five-piece conceptual assembly exist; no measured servo mounting fit, servo model, head center of gravity, travel collision clearance, or structural safety is established.
4. **Electrical:** exact servo, motor controller, power source and display models have not been selected or validated here. No KiCad ERC, wiring test or physical stop test is claimable.
5. **Software CI:** Herbie's recent main-branch simulation/software workflows report failures. Exact root cause is not confirmed from the available logs. See [tracking issue](https://github.com/jimedusot-beep/Herbie/issues/59). Do not claim a regression was caused by documentation-only PR #58.

## Engineering decisions still needed, in priority order

1. Verify actually owned components and acquire exact model/datasheet information.
2. Measure the real head mass, center of gravity, servo torque leverage and mount dimensions.
3. Choose the computer, servo-control approach and independent motor supply/protection.
4. Design, review and ERC-check a **real** KiCad schematic; plan physical servo-power interruption and watchdog.
5. Resolve virtual motion protocol differences and specify a separate hardware adapter with fail-safe behavior.
6. Complete the [readiness gates](../integration/BUILD_READINESS_CHECKLIST.md) and collect physical measurements in `tests/` before enabling motion.
